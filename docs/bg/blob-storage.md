# Локално упражнение с Azure Blob Storage

[English](../blob-storage.md) | [Български](blob-storage.md)

Незадължителното упражнение качва седемте измислени Markdown процедури в **Azurite** —
локалния Azure Storage емулатор на Microsoft. Python използва официалния `azure-storage-blob`
SDK за качване, списък с метаданни и изтегляне на оригиналите. Не са нужни Azure акаунт,
абонамент, вход, платежна карта или облачен ресурс. Проверка с емулатор не е проверка на облачен Storage.

## Стартиране на емулатора

Необходими са Python средата на проекта, Node.js 22+ и pnpm 11.25.0. Това са инструменти за
разработка, а не JavaScript frontend. `tools/azurite/package.json` фиксира Azurite 3.37.0;
`pnpm-lock.yaml` фиксира косвените му зависимости. `uv.lock` фиксира Python SDK 12.31.0 и
неговите зависимости. Ако pnpm липсва, вижте [официалната инсталация](https://pnpm.io/installation).
За първоначалното инсталиране е нужен интернет; след това емулаторът работи локално.

От корена на хранилището в PowerShell:

```powershell
uv sync --frozen --python 3.12
node --version
pnpm --version
pnpm --dir tools/azurite install --frozen-lockfile --ignore-scripts --store-dir ../../.pnpm-store
.\scripts\run_azurite.ps1
```

Оставете терминала да работи. Скриптът стартира само Blob Storage на `127.0.0.1:10000`,
изключва Azurite телеметрията и access логовете и записва данните в изключената от Git
`data/runtime/azurite/`. Не стартира Queue/Table Storage и не създава реален Azure акаунт.
Спира се с Ctrl+C.

Ако системният Node е по-стар от 22, подайте изрично път до налична поддържана версия.
Следващата команда използва вече наличния Node 24, с който е извършена проверката на този
Codex компютър; скриптът не инсталира и не заменя системния Node:

```powershell
.\scripts\run_azurite.ps1 -NodeExecutable "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe"
```

Този Codex път е незадължителен и зависи от средата. На друг компютър използвайте Node 22+
в PATH или реалния път до него. Инсталацията на упражнението не е обновявала съществуващия системен Node 14.

## Работа през интерфейса

Отворете Streamlit приложението и изберете **„Хранилище за документи“** / **Document storage**.

1. Натиснете **„Качи примерните процедури“**. SDK създава частния контейнер в емулатора
   `pharmaops-procedures`, ако липсва, и качва само примерните файлове в `data/procedures/`.
2. Обновете списъка и изберете файл. Разгледайте идентификатора, заглавието, версията,
   държавата, датата на влизане в сила, статуса current/superseded, размера, ETag и SHA-256.
3. Натиснете **„Подготви проверено изтегляне“**, после **„Изтегли оригиналната процедура“**.
   Оригиналният английски Markdown се връща след проверка на размер, хеш и метаданни в заглавната част.

Табът е двуезичен. Отварянето на приложението не се свързва с Azurite; операциите се
изпълняват само след съответния бутон. Недостъпен емулатор показва полезно съобщение.
Съществуващите процеси за процедури и оплаквания не изискват този емулатор.

## Демонстрация от командния ред

При работещ Azurite използвайте друг терминал:

```powershell
uv run --frozen python -m pharmaops.blob_storage publish
uv run --frozen python -m pharmaops.blob_storage list
uv run --frozen python -m pharmaops.blob_storage download --name 01-damage.md
uv run --frozen python -m pharmaops.blob_storage check
```

Изтеглените файлове отиват в изключената от Git `data/runtime/blob-downloads/`. Командата
`check` изпраща реални Azure SDK HTTP заявки към Azurite: качва седемте документа, сравнява
изтеглените байтове и метаданни с оригиналите, качва отново и проверява, че броят обекти
остава седем. Това е отделно от offline тестовете със заместител на storage клиента.

Повторното качване нарочно заменя същите имена. Не създава история на документи и не трие
други blobs. Списъкът допуска само известни примерни имена и най-много 100 обходени обекта;
всяка процедура е ограничена до 256,000 байта. Markdown остава непроменен, включително
заменената процедура и нейният статус. Хранилището не решава приложимостта на процедурите.

## Граница с RAG и бизнес данните

Новата библиотека е упражнение за storage интеграция. Не преиндексира автоматично blobs,
не заменя локалния примерен корпус, не променя векторното търсене и не качва оплаквания,
история на разговори, `.env`, бази или лични файлове. RAG индексът продължава да се изгражда
от `data/procedures/` със собствени филтри за държава/статус/дата. Контролиран процес за
зареждане от Blob към индекса би бил отделна бъдеща промяна.

Storage методите не са агентни инструменти. Адресът на SDK е фиксиран към локалния емулатор;
моделът и UI входът не избират облачен акаунт или произволни файлови пътища. Изтегленото
съдържание остава недоверени данни и не дава разрешение за инструменти или подаване.

## Удостоверяване, съвместимост и ограничения

Реализацията използва публично документираните Azurite development акаунт и ключ на Microsoft.
Този публичен ключ за емулатора не е production тайна. Storage модулът не чете реални облачни
connection strings или ключове. Клиентът изключва използването на proxy от средата, има
timeout от три секунди за свързване и пет за четене и няма автоматични повторения.

Клиентът изрично заявява Storage API версия `2023-11-03`, която поддържа показаните основни
операции и се приема от фиксирания емулатор. Проверката на API версията остава включена;
няма `--skipApiVersionCheck` или loose mode. Така не се разчита на по-нова версия, която
SDK може да избере по подразбиране.

Проверките на SHA-256 и заглавната част откриват несъответствия между изтеглено съдържание
и метаданни; не доказват автентичност, ако някой може да промени и двете. Облачни RBAC,
managed identity, SAS, Key Vault, настройки за шифроване, устойчивост на съхранението,
мащабиране и внедряване не са проверени. Споделеният ключ за емулатора е само за localhost разработка.

При проблем стартирайте Azurite преди качване, проверете Node 22+ и порт 10000 и качете
отново, ако контейнерът липсва. Частично неуспешно качване може да остави някои файлове;
повторението заменя същите примерни имена. Неуспешна проверка за цялост изисква преглед
и ново качване, а не тихо приемане на променения файл.

Вижте [Microsoft Azurite ръководството](https://learn.microsoft.com/en-us/azure/storage/common/storage-install-azurite?tabs=npm),
[официалния Python Blob пример](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-quickstart-blobs-python)
и [публичните development credentials](https://github.com/Azure/Azurite#default-storage-account).
