# Azure Functions локално — без необходимост от абонамент

[English](../azure-local.md) | [Български](azure-local.md)

Незадължителният адаптер изпълнява съществуващия симулиран бизнес API в реалната локална
среда на Azure Functions. Не изисква Azure акаунт, абонамент, карта, `az login` или внедрен
ресурс. Показва локална разработка с Azure Functions, а не облачно внедряване.

За отделно Azure SDK упражнение вижте [локалния Blob Storage](blob-storage.md). Тази
незадължителна библиотека използва Azurite; HTTP Functions host-ът продължава да работи и без него.

## Какво се изпълнява

`function_app.py` използва официалния `azure-functions` SDK и Python v2 модела за програмиране.
`AsgiFunctionApp` адаптира съществуващото FastAPI приложение към HTTP-triggered функция с име
`pharmaops_business_api`. ASGI lifecycle инициализира същата SQLite схема и измислени доставки
като варианта с Uvicorn. Маршрутизацията, валидацията, версиите на чернови, изричното
потвърждение и защитата от дублиране остават в общия FastAPI код.

`host.json` премахва стандартния префикс `api`, така че пътищата до endpoint-ите остават същите.
Помощният скрипт стартира Core Tools на `127.0.0.1:7071`. Той избира Python средата на проекта
само за този процес и възстановява предишните променливи при спиране на host-а.
Създава изключения от Git `local.settings.json` от примера без ключове само ако файлът липсва.
HTTP конфигурацията използва локални файлове за host secret storage. Провереният вариант
не изисква Azure Storage акаунт, Azurite, Docker, Node.js или изтегляне на нов модел.

## Изисквания и стартиране

Използвайте Python 3.12, uv и Azure Functions Core Tools v4. Локалната проверка използва
Core Tools 4.14.0 и `azure-functions` 1.25.0; `uv.lock` фиксира SDK зависимостта. Core Tools
е отделна Microsoft инсталация и не се инсталира чрез `uv sync`. Ако липсва, следвайте
[официалните инструкции](https://learn.microsoft.com/en-us/azure/azure-functions/functions-run-local).
Не е необходим вход с Azure CLI. За първоначалната инсталация на зависимости може да е нужен интернет.

От корена на хранилището в Windows PowerShell:

```powershell
uv sync --frozen --python 3.12
func --version
.\scripts\run_functions.ps1
```

Оставете този терминал да работи. Във втори терминал:

```powershell
Invoke-RestMethod http://127.0.0.1:7071/health
Invoke-RestMethod http://127.0.0.1:7071/deliveries/DEL-1002
uv run --frozen python -m scripts.check_functions
```

Последната команда изпраща реални localhost HTTP заявки с `BusinessClient`. Проверява
достъпността, справка за доставка, непозната доставка, отказ на остаряло потвърждение и
повторно подаване. Създава едно изрично измислено оплакване и показва върнатия номер.
Това е нарочна интеграционна проверка, а не реално бизнес подаване или оценка на LLM.

Uvicorn API на порт 8000 и Functions на 7071 могат да работят едновременно. Използват един
локален SQLite файл и затова споделят симулираните записи. Спирайте Functions с Ctrl+C в неговия терминал.

## Свързване на съществуващия интерфейс

Адресът на API остава под контрола на оператора. В друг PowerShell терминал:

```powershell
$env:BUSINESS_API_URL = "http://127.0.0.1:7071"
uv run --frozen streamlit run app.py --server.address 127.0.0.1 --server.port 8502
```

Отворете [допълнителния интерфейс](http://127.0.0.1:8502). Отделният порт запазва работещ
интерфейс на 8501. Режимът на модела продължава да идва от `.env`: Groq е отделен доставчик,
а mock остава видимо означена симулация. В тази версия Azure Functions изпълнява само
бизнес API; не заменя LLM, embeddings, Chroma или агентния граф. Затворете терминала след
работа, за да отпадне временната настройка за API URL.

## Какво демонстрира за интервю

- Python Azure Functions HTTP интеграция с официалните локални host и SDK.
- Адаптиране на ASGI API с една обща реализация на бизнес валидацията.
- Настройки на host/worker, локални HTTP проверки и диагностика на неуспешни заявки.
- Разграничаване на локалната разработка от създаване на Azure ресурси, удостоверяване и внедряване.

Точно описание е: „Локална разработка и тестване с Azure Functions, Python, Core Tools и
FastAPI интеграция; не е изпълнявано облачно внедряване.“

Подгответе обяснение за HTTP trigger, `AsgiFunctionApp`, ролята на `host.json` и
`local.settings.json`, смяната на адреса от клиента и причината повторните заявки да връщат
един референтен номер.

## Ограничения и отстраняване на проблеми

Няма облачно внедряване, Azure OpenAI/Foundry inference, AI Search, проверка на Entra ID /
managed identity, Key Vault интеграция или облачна Application Insights телеметрия.
Локалният SQLite и анонимният HTTP достъп са демонстрационни решения, а не production
Functions архитектура. `.funcignore` изключва тайните и runtime данните от евентуално
пакетиране, но пакетиране и внедряване не са проверявани и не се предоставя deployment команда.

- Липсва Python: изпълнете sync командата преди скрипта. Той очаква `.venv` в това хранилище.
- Липсва `func`: инсталирайте официалния Core Tools v4. За локалния host не е нужна платена Azure услуга.
- Порт 7071 е зает: спрете предишния локален Functions процес; не променяйте несвързани услуги.
- Host-ът стартира, но HTTP заявките не работят: проверете терминала, наличието на индексирана
  `pharmaops_business_api` и използвайте посочените коренови пътища без допълнителен `/api` префикс.
- Нов trigger, изискващ Storage, е извън тази HTTP конфигурация. Такова разширение може да
  изисква емулатор като Azurite или отделно конфигурирана Azure услуга.
- Пазете `local.settings.json`, локалните host файлове, SQLite данните и `.env` извън Git.
  В примерните настройки не трябва да има облачни connection strings.

Вижте [Microsoft ръководството за локална разработка](https://learn.microsoft.com/en-us/azure/azure-functions/functions-run-local)
и [официалния ASGI адаптер](https://learn.microsoft.com/en-us/python/api/azure-functions/azure.functions.asgifunctionapp?view=azure-python).
