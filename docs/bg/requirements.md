## Потребителски истории и критерии за приемане

| Приоритет | Потребителска история | Критерии за приемане |
| --- | --- | --- |
| P0 | Като служител по приемане искам приложимата процедура за опаковки. | Избрана е държава; извличат се само текущи глобални/местни откъси в сила; всеки показан оригинален откъс има валиден цитат и разгъваеми метаданни. |
| P0 | Като служител искам честен отговор при липса на доказателства. | Неподкрепените отговори се спират; въпроси извън обхвата се отказват; липсваща или неясна държава води до искане за уточнение. |
| P0 | Като служител искам да запиша оплакване за доставка. | Приложението прави HTTP справка за доставката; проверява задължителните полета; извлича процедура; запазва и показва структурирана чернова. |
| P0 | Като служител трябва да контролирам подаването. | Графът няма инструмент за подаване; необходимо е изрично UI потвърждение; промени в полетата го изключват; стари сървърни версии се отхвърлят. |
| P0 | Като служител искам безопасно повторение. | Повторни и едновременни подавания на една потвърдена чернова връщат един номер и създават един запис. |
| P0 | Като демонстриращ проекта искам offline проверки. | Lint и тестовете работят с mock модели и тестови embeddings без ключове или изтегляне на модели. |
| P1 | Като оценяващ искам честен преглед на модела. | Retrieval с реални embeddings и незадължителните реални LLM примери са отделени от offline тестовете; непроверените възможности са означени. |
| P1 | Като потребител искам полезни грешки. | Непознати доставки, недостъпен API/модел, липсващ индекс и невалидни полета дават указания за действие; не се показва сурово изключение с ключ. |
| P1 | Като двуезичен демонстратор искам английски и български. | Превключвателят превежда UI и съобщенията; българските въпроси работят с реален модел; английските цитати остават достъпни; въведеното във формуляра се запазва при смяна на езика. |
| P1 | Като собственик на проекта искам документация на двата езика. | README и техническите документи в `docs/` имат английска/българска версия и взаимни връзки; командите и записаните резултати съответстват; промените обновяват и двата езика. |
| P1 | Като демонстратор искам Blob упражнение без абонамент. | В Azurite се качват само примерните процедури, метаданните се запазват, оригиналите се проверяват при изтегляне и основното приложение работи без емулатора. |

## Съответствие с изискванията за позицията

| Изискване | Реализирано в проекта | Оставаща липса |
| --- | --- | --- |
| Python и API | Pydantic схеми, FastAPI, HTTPX, SQLite транзакции | Няма достъп до реална бизнес система |
| LLM и prompt engineering | Groq / локален съвместим адаптер, структуриран JSON, инструкции за отговор само по източници | Качеството зависи от модела; необходими са по-широки оценки |
| RAG и векторно търсене | Разделяне по раздели, локални embeddings, Chroma, филтри по метаданни, цитати | Малък английски корпус; няма хибридно търсене или reranker |
| AI агенти и инструменти | Моделът избира от разрешени инструменти в ограничен LangGraph процес | Ограничени агенти за конкретни задачи, без общо автономно планиране |
| Тестване и CI/CD | pytest, Ruff, фиксирани зависимости, GitHub Actions CI конфигурация | Hosted CI трябва да се провери след разрешен push; няма CD |
| Сигурност | Изключени тайни, фиксирани адреси, схеми, потвърждение, параметризиран SQL | Локално демо без production система за вход или нормативна сертификация |
| Бизнес комуникация | Изисквания, списък с действия, демо сценарий, архитектура и ограничения | Няма интервюта с реални заинтересовани страни или проучване за приемане |
| Azure / облак | Локална Azure Functions интеграция и реални Blob SDK заявки към Azurite без абонамент | Няма проверка на облачно внедряване, managed identity или Azure AI услуги |
| Дълбоко обучение | Използват се предварително обучени езикови и embedding модели | Няма обучение или fine-tuning на модел |

## Следващи стъпки по приоритет

1. Разширяване на въпросите с източници, означени от човек, и ръчна оценка на пълнота,
   релевантност и правилен отказ от отговор.
2. Проверка на незадължителен локален чат модел и описание на точната среда и настройки.
3. Преглед на историята на черновите и възстановяване на сесии без глобално споделяне на разговори.
4. Оценка на приоритета на държавни допълнения, противоречиви процедури и историческа валидност.
5. Удостоверяване и права само ако проектът излезе извън локалното демо.

Качване на документи, допълнителни агенти, имейли, Azure инфраструктура и JavaScript frontend
са извън първата версия. Незадължителният локален Functions host не създава облачна инфраструктура.
Не се твърдят production готовност, принадлежност към организация, облачно внедряване или клинична пригодност.
