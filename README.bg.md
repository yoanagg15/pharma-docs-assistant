# PharmaOps AI — Асистент за дистрибуционни операции

[English](README.md) | [Български](README.bg.md)

Независим портфолио проект за начинаещ Python / AI разработчик. Служители могат да разглеждат
измислени дистрибуционни процедури и да подготвят оплаквания за доставки, след което изрично
да потвърдят подаването им към **симулиран** бизнес API. Проектът не е свързан с реална
фармацевтична компания. Процедурите са примерни оперативни документи, а не медицински или
нормативни указания.

## Възможности

- Семантично извличане на приложими за държавата документи с разгъваеми метаданни и откъси.
- Интеграция с Groq API (има Free план с ограничения), незадължителен локален сървър с
  OpenAI-съвместим API и ясно означен mock режим с отговори по фиксирани правила. Ollama не е необходим.
- Ограничен LangGraph процес, в който моделът избира инструменти, а кодът налага проверките.
- Структурирани отговори с извлечени цитати: всяко показано оригинално твърдение трябва да е
  точен цитат от посочения откъс. Българският превод се показва отделно.
- Десет измислени доставки в BG, DE и RO; версии на черновите и защита от дублирано подаване.
- Отделно състояние за всяка Streamlit сесия, полезни съобщения за грешки и списък с действия
  без показване на скрити разсъждения.
- Превключвател English / Български за интерфейса и отговорите. Оригиналните източници остават
  на английски; означените български преводи не заменят проверката на цитатите.
- Offline тестове с pytest и GitHub Actions CI. Не е реализирано и не се твърди облачно внедряване.
- Незадължителен локален Azure Functions host за същия бизнес API без Azure абонамент.
- Незадължителен двуезичен таб „Хранилище за документи“ с реални Azure Blob SDK заявки към
  локален Azurite: качване на примерни процедури, метаданни и проверени оригинали за изтегляне.

## Архитектура

Streamlit → ограничен LangGraph процес → LangChain инструменти → локален Chroma / симулиран FastAPI → SQLite.
Groq изпълнява езиковия модел, а FastEmbed изчислява локални ONNX embeddings. Конфигуриран
локален OpenAI-съвместим сървър, например LM Studio, може да замени Groq. Интерфейсът никога
не отваря директно бизнес базата.
Вижте [архитектурата](docs/bg/architecture.md), [изискванията](docs/bg/requirements.md),
[сценария за демонстрация](docs/bg/demo-script.md) и [учебните бележки](docs/bg/learning-notes.md).

## Настройка в Windows PowerShell

Необходими са Windows, Python 3.12 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Проектът допуска и Python 3.13; проверките са изпълнени с 3.12. За инсталацията на пакетите и
първоначалното изтегляне на embedding модела е необходим интернет. API акаунт е необходим
само за Groq режима.

```powershell
Set-Location D:\_AI\pharma-docs-assistant\pharma-docs-assistant
uv python install 3.12  # Skip if already installed
uv sync --frozen --python 3.12
Copy-Item .env.example .env  # Only if .env does not already exist; never overwrite your key
notepad .env
```

Пропуснете инсталирането на Python, ако вече е наличен. Копирайте `.env.example` само ако
нямате `.env`, за да не презапишете ключа си.

`uv.lock` фиксира преките и косвените зависимости. `uv sync --frozen` възпроизвежда избраните
версии, а `pyproject.toml` описва допустимите диапазони. Не включвайте в commit `.env`, кешове
на модели, бази, индекси или локални оценъчни отчети. Те са изключени чрез `.gitignore`.

## Достъп до езиков модел

Препоръчителната настройка за тази среда е ключ от [Groq Console](https://console.groq.com/keys),
Free план и следните стойности в `.env`:

```dotenv
MODEL_PROVIDER=groq
GROQ_API_KEY=your_key_here
MODEL_NAME=qwen/qwen3.8-27b
```

Никога не поставяйте ключа в чат, изходен код, екранна снимка или Git. Безплатните квоти и
достъпните модели могат да се променят: проверявайте [лимитите](https://console.groq.com/docs/rate-limits)
и [моделите на Groq](https://console.groq.com/docs/models). Безплатният акаунт не означава
неограничен достъп. Няма автоматично преминаване към плащане или смяна на доставчика.
Изпращайте само измислени въпроси и откъси от процедури. Приложението изключва LangSmith tracing.

За работа без API ключ:

```dotenv
MODEL_PROVIDER=mock
```

Mock режимът е симулация за разработка по фиксирани правила, **а не демонстрация на реален LLM**.
В интерфейса той продължава да използва реалния семантичен индекс. Само автоматичните offline
тестове използват заместители на embedding векторите.

За вече наличен локален сървър с OpenAI-съвместим API, който проектът не инсталира:

```dotenv
MODEL_PROVIDER=local
LOCAL_LLM_URL=http://127.0.0.1:1234/v1
MODEL_NAME=your_loaded_model_id
```

Сървърът и моделът трябва да поддържат JSON режим и достатъчен контекст за откъсите.
Съвместимостта трябва да се провери с конкретния модел; наличието на адаптер в кода не означава
проверена локална среда. Не се инсталират автоматично локален LLM или негови тегла.

## Изграждане или обновяване на индекса

```powershell
uv run --frozen python -m pharmaops.cli index
```

При първото изграждане FastEmbed изтегля `BAAI/bge-small-en-v1.5` — квантизиран ONNX модел с
размер от порядъка на десетки MB; пълният кеш е по-голям. Това е локален embedding модел,
а не чат LLM. Работи на CPU и не изисква платен API. Ако е недостъпен, командата показва
полезна грешка; няма скрито заместване с търсене по ключови думи. Изтеглените файлове и
данните на Chroma остават в `data/runtime/`. Следващи стартирания могат да използват кеширания модел.

Изградете индекса отново след промяна на документите или embedding модела. Идентификаторът на
колекцията зависи от корпуса и модела, а manifest файл избира завършеното изграждане. Така
след успешно обновяване не се използва случайно стар корпус. Предишните колекции остават
локално, но не участват в заявките.

## Стартиране на услугите

В първи PowerShell терминал от директорията на проекта:

```powershell
uv run --frozen uvicorn pharmaops.business:app --host 127.0.0.1 --port 8000
```

Във втори терминал:

```powershell
uv run --frozen streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

Отворете [интерфейса](http://127.0.0.1:8501), [API документацията](http://127.0.0.1:8000/docs)
или [проверката за достъпност](http://127.0.0.1:8000/health). И двете услуги слушат само на
localhost. Спират се с Ctrl+C в съответния терминал. При първото стартиране API автоматично
създава SQLite таблиците и десетте измислени доставки.

Изберете BG и задайте началния въпрос за повредена опаковка. След това подгответе оплакване
за DEL-1002 с описание `Outer carton torn at the corner.` и един засегнат пакет. Прегледайте
източниците и черновата; маркирайте потвърждението и натиснете **„Потвърди и подай оплакването“**
(**Confirm and submit complaint** в английския интерфейс). Повторното подаване връща
първоначалния референтен номер. Промени в полетата изключват потвърждението, докато обновената
чернова не бъде запазена и прегледана. След подаване използвайте **„Ново оплакване“** / **Start a new complaint**.

## Проверки и оценки

За Azure упражнение без акаунт или абонамент вижте [локалния Azure Functions вариант](docs/bg/azure-local.md).
При инсталиран Core Tools v4 API се стартира с `.\scripts\run_functions.ps1` на порт 7071.
Това е локално проверена runtime интеграция, а не облачно внедряване или Azure-hosted AI демонстрация.

Отделното [Blob Storage упражнение](docs/bg/blob-storage.md) използва Azurite на localhost
с официалния Python SDK без Azure абонамент. Необходими са Node 22+ и фиксираният емулатор
за разработка. То не променя RAG корпуса и не качва разговори или оплаквания.

```powershell
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv run --frozen python scripts/check_docs.py
uv run --frozen pytest -q
uv run --frozen python -m pharmaops.cli model-check
uv run --frozen python -m pharmaops.cli evaluate
uv run --frozen python -m pharmaops.cli evaluate --llm --limit 3
```

1. Offline тестовете използват фиксирани тестови embeddings и mock модели без изтегляне на
   модели или външни API. Проверяват договорите между компонентите, филтрите, цитатите, API
   грешките, защитите от инструкции в документи, ограниченото изпълнение на графа, остаряло
   потвърждение и повторни/едновременни подавания.
2. Retrieval оценката използва **реални локални embeddings** върху 14 случая с фиксирана
   референтна дата. Source hit rate@3 е делът на поддържаните въпроси, за които поне един
   очакван източник присъства сред първите три откъса. MRR@3 е средното от `1 / ранг на първия
   релевантен откъс`, или нула, ако такъв липсва. Глобалните и специфичните за държава откъси
   заемат отделни позиции. Няколко откъса от един документ могат да заемат различни позиции.
   Неподдържаните и двусмислените случаи не участват в тези retrieval метрики.
3. Незадължителният `--llm` изпраща реални заявки до доставчика и запазва действителните
   отговори за преглед от човек. Проверката на цитатите е отделна от релевантност и пълнота;
   не се твърди автоматична оценка за качеството на отговорите. Изпълнението с три случая е
   кратка проба, а не цялостна оценка.

Отчетите се записват в изключените от Git `artifacts/retrieval.json` и `artifacts/llm-examples.json`.
По подразбиране между реалните LLM случаи има 12 секунди пауза за намаляване на риска от
ограничаване във Free плана; `--delay 15` увеличава интервала. Моделните грешки се броят отделно.
Използвайте `--reference-date 2026-10-18` за възпроизводимо филтриране. Интерфейсът използва
текущата дата по подразбиране. Вижте [записа на проверките](docs/bg/validation.md) за действително
изпълненото. GitHub Actions е конфигуриран да изпълнява lint, форматиране и offline тестове
без тайни. Това е CI; няма конфигурирано CD.

## Ограничения и отстраняване на проблеми

- Няма production система за вход, изолация между организации, трайно съхранение на разговори
  на сървъра, медицински решения, температурни SOP, имейли или реална бизнес интеграция.
  Не излагайте локалните услуги в публична мрежа.
- Проверката на точните откъси проверява произхода, а не истинност, релевантност или пълнота.
  Извлечените цитати са по-лесни за проверка, но ограничават свободния синтез. Човешкият преглед остава нужен.
- Откриването на злонамерени инструкции е малка евристика, а не пълна защита. Основните граници
  са фиксирани разрешени инструменти, типизирани входове, данни под контрола на API и подаване извън графа.
- Обхватът и държавата се определят чрез ясни правила и избора на процес в интерфейса,
  а не чрез общ класификатор на намерения. Поддържаните демонстрационни държави са BG/DE/RO.
- Косинусовите разстояния не са калибрирани вероятности. Първите три резултата с евристичен
  праг 0.65 могат да пропуснат релевантни откъси или да върнат нерелевантни. Малко разстояние не доказва подкрепа.
- Липсващ индекс: изпълнете командата за индексиране. Неуспешно изтегляне на embedding модел:
  проверете връзката и повторете. Не заменяйте реалните retrieval вектори с тестови.
- Недостъпен API: стартирайте първия терминал. Интерфейсът не заобикаля API с директен запис в SQLite.
- Недостъпен модел / HTTP 429: проверете ключа, модела и квотата; изчакайте и повторете.
  Заявките имат timeout и няма автоматичен платен заместител. Сурови грешки и ключове не се показват.
- Зает локален порт: спрете съществуващата услуга или променете и командата, и съответния `.env` URL.
- Streamlit сесиите се нулират при рестартиране. Бизнес черновите и оплакванията остават
  в SQLite, но малкият интерфейс няма преглед на историята на черновите.

## Езици на документацията

Документацията на проекта се поддържа на английски и български. Всеки документ има връзка
към другата версия; промени в поведението трябва да обновяват и двете едновременно.
Измисленият RAG корпус остава на английски. Вижте [правилата за хранилището](AGENTS.md).
CI проверява за липсваща езикова версия, невалидни локални връзки и разминаващи се блокове с
изпълними команди/настройки чрез `scripts/check_docs.py`. Точността на превода и смисловото
съответствие продължават да изискват човешки преглед.
